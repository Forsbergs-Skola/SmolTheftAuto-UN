## 1. Player Movement System


### Location
`Assets/Scripts/Player/Movement`


### Input & Control Handling


Uses a PlayerControls input actions asset generated by the new Unity Input System. had to learn this new input system
as I only knew the deprecated one


Enables / disables input during game events (did this while paired with Brad)


### Movement Logic


Movement direction is computed differently depending on whether the player is aiming. When aiming you enter a strafe
like movement, facing and rotating with the camera. Otherwise, the movement is free from where the camera is. You can
walk, sprint and jump.


I used a CharacterController component. Due to this gravity is manually applied (no Rigidbody used).


A raycast is fired down from just below the CharacterController to detect valid ground. This helps the player only
jump when on ground. PlayerAnimation is handled in this script (explained in Animation section).


### Combat & Damage Handling

## 3. Weapon System - (Rifle, Shotgun, Grenades, Reloading)




I created and implemented a fully modular gun system, integrating the event system created by Brad for this project.
It is fully customisable, using the Gun class to create firearms. This makes it extremely easy to create different
types of firearms in the future (projectile weapons, snipers, etc.). I also created the grenades and implemented the
reloading with Brad


### Key Features


Modular Weapon Architecture


Each gun uses the Gun class, which handles input and fire logic. Building on top of this are the Hitscan and Shotgun
scripts which handle the different weapon behaviours (how many bullets, spread, isAutomatic, etc.)


Events (via EnumWeaponPayloadEvent) allow the firing, reload, and swap logic to remain independent of gameplay controllers, animations, and audio. (Implemented with Brad)


### Rifle and Pistol – HitscanDamage.cs


Central-screen raycast for instant bullet impact. Shoots directly where the crosshair is.


Damage applied to:


NPCs (NPCHealth) - Integrated by me


Vehicles (VehicleHealth) - Integrated by Ibad


VFX and SFX - Gunshot Noise, Muzzle Flash and Hit Impact Confetti effect.


Modular and customisable. The pistol and rifle use the same script. You can toggle between automatic or not and change
each aspect. This script could be used for multiple different hitscan weapon types (pistol, revolver, rifle, SMG,
machine gun, etc.).


### Shotgun – ShotgunDamage.cs


Fires multiple raycast pellets per shot.


Each pellet receives a random spread calculated using a random 2D point in a circle and the shape is calculated using
a tangent of the spread angle which forms a cone shape,


Independent hit detection for each pellet which applies damage to:


NPC damage - Implemented by me


Vehicle damage - Implemented by Ibad


VFX and SFX - Gunshot Noise, Muzzle Flash and Hit Impact Confetti effect for each pellet.


Flexible pellet count + spread angle for easy tuning allowing the creation of multiple shotguns if desired.


### Grenades – Grenade.cs and GrenadeThrower.cs


Player throws a physical grenade prefab with forward/upward velocity. It explodes after a timed fuse (customisable) and
this damages any NPCs hit and also applies forces to any rigidbodies in its radius. This allows for interaction with
RBs on props and also ragdoll physics.


VFX and SFX - Explosion Noise, Explosion Effect and Explosion Confetti. (I decided to make the grenade a present and
make it Xmas themed.)


Integrated UI event to decrement grenade count (paired with Brad)


### Weapon Switching System


0 - Empty hands
1 - Pistol
2 - Rifle
3 - Shotgun


Tied into a global GameManagerSingleton to update ammo state and equipped weapon. (Paired with Brad)


### Reload System (Built with Brad — Event-Driven & Fully Modular)


I collaborated with Brad to implement the fully event-driven reload system that works across all weapon types.


Reload actions do not live inside the weapon scripts → instead they’re driven by centralised event systems.


The Gun class only triggers:


reloadEvent.TriggerEvent(EnumWeapon.X)


Reload logic (ammo calculations, animation timing, SFX cues) happens elsewhere, making it easy to add new weapons,
adjust timings, deal with animations and refill the ammo separately. This makes the system very scalable and easy to
expand on and debug


### Code Architecture Summary


**Gun.cs**
Handles firing behaviour, cooldowns, input detection, animation triggers, and event dispatch.


**HitscanDamage.cs / ShotgunDamage.cs**
Modular per-weapon behaviours using different raycast systems.


**GrenadeThrower.cs / Grenade.cs**
Physics throwing, explosion logic, visual/audio effects, and gameplay impact.


**WeaponSwitcher.cs**
Input-based weapon switching with event broadcasting.
